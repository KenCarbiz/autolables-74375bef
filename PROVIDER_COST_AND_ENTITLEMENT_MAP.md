# Provider Cost and Entitlement Map (Gate 1, Agent 2)

Repo `KenCarbiz/autolables-74375bef` at `main`; live project `onnbmmdbrsgytfozfozn`; pilot tenant Harte Infiniti `3f0f97f5-4151-4e32-88ef-e2d6fc5a3142`. Live figures were read 2026-09-09 between 08:15Z and 08:40Z with read-only SELECTs (query list in the Evidence index, Q1-Q36; Q31-Q36 were added in the cross-review revision, same day 09:05-09:25Z). ## Executive summary

1. Twenty-six edge functions touch an external provider. Only ONE meters its calls in code: `marketcheck-sync` (`_shared/mcCost.ts` public list prices, written to `marketcheck_sync_config.last_status.api_usage`). `vehicle-enrich`, `marketcheck-specs`, `marketcheck-comps`, `marketcheck-recalls`, `marketcheck-market-pricing`, `marketcheck-incentives` do not import `mcCost.ts` at all, so roughly 80 percent of MarketCheck call volume is unmetered (Q14: nightly sync is 8 calls; enrich is 6-10 calls per VIN across 130 VINs).
2. No provider has a hard dollar budget. The only spend controls are count caps, TTL skips, attempt caps, service locks and pacing. The description generator is the only subsystem with a dollar budget, and it cannot bind because every one of its 1,294 executions is `cost_state = 'unavailable'` (Q17; model `gpt-5.6-luna` has no pricing row).
3. Two metering tables that the code writes to DO NOT EXIST in the live database: `title_report_pulls` (NMVTIS meter and 50/month cap, `marketcheck-title-report/index.ts:148-172,243`) and `marketcheck_comps_cache` (12 h comps cache, `marketcheck-comps/index.ts:78-90`). `vehicle_listings.title_verification` is also absent (Q23, Q29). Both writers swallow the error, so the NMVTIS cap reads 0 spent forever, and every `marketcheck-comps` call is a paid search. That call is reachable only from the V2Detail route `/v/:slug/comparable-vehicles` (`src/App.tsx:297` -> `VehiclePassportV2Detail.tsx:986-988,1370`); the served, locked Passport opens the `comparable-vehicles` PassportPanel (`VehiclePassportGoverned.tsx:930,1366,1504,1510` -> `openPanel` :379-384 -> `PassportPanel.tsx:796`), which makes no provider call. The comps cost exposure is therefore LATENT (typed-URL or bot path; 0 `mc_comps_lookup` rows in 4 days, Q15), and the missing cache table is a defect, not a live spend. Consumer-visible consequence of the absent NMVTIS ledger: the Compliance tab meter reads a false zero (§1.7).
4. Every §19 MarketCheck listing field is PRESENT in the stored feed payload (`vehicle_listings.mc_raw`, 128/130 published Harte rows, Q3-Q4): `last_seen_at`, `first_seen_at`, `first_seen_at_mc`, `first_seen_at_source`, `scraped_at`, `dom`, `dom_active`, `dom_180`, `dos_active`, `price_change_percent` (120), `ref_price` (120), `ref_price_dt` (120), `in_transit` (128, all false). Only a subset is copied into `mc_attributes` (`marketcheck-sync/index.ts:1148-1156`); `first_seen_at_mc`, `first_seen_at_source`, `dos_active`, `ref_price_dt`, `data_source`, `vehicle_status` live only in `mc_raw`. MDS, comparables, listing history and sold stats come from `vehicle-enrich`, not the feed.
5. Source Health inputs exist for every source but are scattered across seven tables and three JSON columns; none is a single view. Last-success is answerable for MarketCheck inventory (`inventory_sync_runs`), Firecrawl (`advertised_price_crawl_attempts`, `audit_log`), NeoVIN (`neovin_snapshots.fetched_at`, `provider_payload_shapes.last_seen_at`), EPA/recall/market (per-listing `*_checked_at` maxima). Last-failure is answerable only for MarketCheck sync, Firecrawl, OEM copies and descriptions.
6. Per-tenant enable switches exist for MarketCheck inventory (`marketcheck_sync_config.allowed/enabled`), OEM incentives (`tenant_incentive_settings.incentives_enabled`, 0 rows live) and NMVTIS (`app_entitlements.plan_tier = compliance_pro`). Enrichment, NeoVIN decode, recalls, EPA, Firecrawl crawl, OEM document harvest, descriptions and Google reviews have NO tenant switch; they run for every tenant with inventory. Paid provider data also leaves the tenant through two sister-app channels with different deny rules (`autofilm-feed` via `LOT_FEED_DENY`, `vehicle-lookup` via its own `COLS` list) and through the anonymous `public-listing-view`; the licensing status of that redistribution is UNKNOWN / REVIEW REQUIRED (new §9). Separately (Gate 1 inspection, I1-db): the RPC behind the anonymous view, `get_vehicle_listing_by_slug`, is `SECURITY DEFINER`, returns `SELECT * FROM vehicle_listings`, and is EXECUTE-granted to `anon`, so the edge function's deny-list is bypassable by any holder of the anon key (§9, recorded as a proposal, not applied).
7. Global kill switches: `MARKETCHECK_INCENTIVES_ENABLED` (off by owner decision 2026-07-28), missing API keys for VinAudit/MonroneyLabels and Black Book (both return `not_configured` at HTTP 200), `ENRICH_INCLUDE_MDS`. There is no kill switch for `vehicle-enrich`, `marketcheck-specs`, `marketcheck-comps` or the crawler other than removing the key.
8. Cost exposure ranking (list price or measured): Firecrawl crawl up to 100 renders/day at 1 credit each against a 1,000-credit plan (Gate 0 report §5.6); MarketCheck nightly sync about $7 list ($210/month projected, Q14); enrich sweep about $0.17 list per VIN visited (unmetered); NeoVIN $0.08 list per decode (attempt-capped at 3); description model spend unmeasurable; NMVTIS $0.49 per generate with a broken cap; OEM incentives $0.20 list per call (globally off).
9. Firecrawl is the only provider with a code-verified unit cost (1 credit per render, Gate 0 §5.6) and the only one whose balance is read before spending (`_shared/renderKey.ts`). MarketCheck contract pricing is UNKNOWN; `mcCost.ts:3-6` states its figures are public list prices captured 2026-08-01.
10. Failure modes observed at Gate 0 that bear on cost: 144 x 402 and 181 x 429 Firecrawl refusals against an exhausted team key (fixed by balance-based key selection); the 06:00Z crawl gateway 504 with a paid render lost (fixed by chaining); guard-refused new-car VDPs re-rendered every run (fixed by 7-day backoff); description count cap exceeded two days running (562, 506); `sold_stats` ladder failing 100 percent of the time for a week at about 18 percent of metered calls (`vehicle-enrich/index.ts:570-575`).
