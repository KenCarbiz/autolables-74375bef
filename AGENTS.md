# Agent rules

- Files.com inventory intake lives in `supabase/functions/files-inventory-notify` (signed webhook receiver) and `files-inventory-admin` (platform-admin console), with pure rules in `supabase/functions/_shared/filescom/`. Why: the tenant is derived only from an admin-approved exact-path binding, never from a request header or filename.
- Files.com connector TypeScript writes only its ledger, queue and staging tables (`inventory_feed_*`, `inventory_store_snapshots`, `inventory_snapshot_vehicles`; enforced by `assertConnectorWrite`). Inventory is written only by the SQL function `inventory_apply_store_snapshot`, one transaction per store snapshot. Why: phase 2 (owner-approved 2026-10-31) adds per-store imports, but a failed or partial snapshot must never partially replace a store's inventory.
- Each feed partition (vAuto DealerId) needs an approved `inventory_source_mappings` row to its store; unmapped, pending or changed identities are quarantined. Ingestion starts paused; sold/retire automation, sibling sharing and MarketCheck enrichment are separate per-store switches that default off. Why: approval of the file, the dealer identity, sharing and paid calls are separate decisions.
- Per-VIN MarketCheck calls for store-owned vehicles pass `store_enrichment_admit` inside `admitProviderCall`. Never call MarketCheck from ingestion, webhooks or customer browsing. Rollout steps: `docs/filescom-multistore-rollout.md`.
