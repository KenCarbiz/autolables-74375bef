## Executive summary

1. The browser assembles one vehicle from at least 48 distinct read sites (41 vehicle-truth readers plus the 7 Vehicle File activity / evidence / signature readers R1a-R1g) and the edge tier from 28 more; `vehicle_listings` is read with `select("*")` by 14 of them and with named columns by the rest, so no two surfaces read the same column set (§A).
2. Advertised retail has five live homes: `vehicle_listings.price` (feed, fee-inclusive), `vehicle_listings.website_sale_price` / `advertised_price_before_doc` (crawler ladder), `advertised_prices` rows (feed + website channels), `vehicle_facts.advertised_price` and `vehicle_snapshots.pricing.advertisedPrice`. The served Passport input is mode-dependent (`resolveDisplayPrice`, `priceModel.ts:196-213`); on Harte (`price_display_mode = website_sale_price`, fee-inclusive) it is `vehicle_listings.price`, not the crawler ladder (§C1). Today on Harte: latest website capture disagrees with `price` on 9 of 20 VINs (5 of them same-day captures, so the shopper's Passport total differs from the dealer's own page on those 5); the newest `vehicle_facts.advertised_price` disagrees on 99 of 117; the snapshot on 99 of 117; `website_sale_price` on 5 of 128 (§C1).
3. `verify_addendum_price` picks the website channel FIRST regardless of age, so a July capture of $90,403 on `JN8AZ3AE1T9720885` (feed $78,084) is the number the signing gate would compare against today; two more Harte VINs carry the same stale-above-feed website row (`JN8AZ3CC9T9622022` 109,195 vs 103,090; `5N1AL1FS7TC339685` 63,120 vs 60,893) (§C1 worked example 3, §F5).
4. Stock has no column on `vehicle_listings`; readers resolve it from `vehicle_files.stock_number` (7 readers; the Vehicle File header reaches it only third in the `vehicleStockNumber` precedence), `mc_attributes.stock_no` (6 readers, populated on 0 of 130), `sticker_snapshot.stock_number` (3 readers, populated on 0 of 130, so the Compliance Center stock and the CommandPalette stock search are dead on Harte), `get_ready_records.stock_number` (blank on 24 of 130), `safety_inspections.stock_number` (58 of 58), or a phantom `vehicle_listings.stock_number` column (7 readers whose SELECT cannot succeed) (§C4, §D).
5. MSRP is read from `mc_attributes.msrp` (Passport, sticker stale check, lot feed), `vehicle_files.msrp` (0 on all 284 rows) and `vehicle_snapshots.pricing.totalMsrp` (differs from `mc_attributes.msrp` on 104 of 125) (§C5).
6. Recall status has two parallel stores written by the same function: `recall_check` JSON (read by the publish trigger, the stale-recall sweep and the Command Center) and `recall_status` + `open_recall_count` (read by the Passport, Vehicle File, Compliance Center, clearance and lifecycle). 120 of 130 published listings have no `recall_check`; 74 have no `recall_status`; every `do_not_drive` substring test against `recall_status` is dead because that column only ever holds `clear` / `open_recalls` (§C6).
7. Title verification is broken at the schema: `vehicle_listings.title_verification` does not exist (write at `TitleVerificationPanel.tsx:124`, read at `passportV2Data.ts:582`), `title_report_pulls` does not exist (read at `marketcheck-title-report/index.ts:150-154`), and no active VIN carries a title brand, a CARFAX clean-title flag, or a title/MCO document (§C7, §D).
8. Get Ready operational facts on Harte are 100% seeded and 0% executed: 130 `get_ready_records` all `pending` / `ingest_autogen`, 0 signed inspections, 0 prep / detail / PDI sign-offs, 0 install proofs, 0 work events, 58 of 58 used vehicles `blocked_inspection_not_started` yet all 58 are `published`; 9 published used VINs carry lifecycle state `REMOVED` (§C8, §E).
9. Documents: `signed_document_archive` holds 129 `buyers_guide` rows covering 71 of 130 active VINs (58 used, 13 new) while `generated_documents` shows 1 published + 70 drafts; the deal gate (`process-deal`) answers "no Buyers Guide" for 57 of 58 used cars while the nightly audit answers "present" for 58 of 58 (§C9).
10. Consolidation candidates are ranked in §G with a wrong selling price first; the read model should own price (one derivation), stock (one read-model field sourced from `vehicle_files.stock_number`), recall (one store), Get Ready/clearance (one server projection), documents (one status source) and the listing timeline (`vehicle_change_history` / `vehicle_value_history` have 6,703 / 6,696 Harte rows and zero employee readers, §C11) before any UI cutover.

## Method

- Code: every `.from('<table>')`, `.rpc(...)`, `functions.invoke(...)` under `src/` and `supabase/functions/` was enumerated (`grep -rnE "\.from\(['\"]..."`), then each read site was opened and its select list + transform recorded. SQL functions/views/triggers were read from the live catalog (`pg_get_functiondef`, `information_schema.views`, `pg_trigger`), not from migrations.
- Data: read-only SELECTs through the Lovable MCP tool against the public schema. Result sets were aggregated; per-VIN examples are limited to what the worked examples need.
- Not touched: `src/pages/VehiclePassportGoverned.tsx` and its price arithmetic are mapped only (§4 of the directive).
