## Executive summary

1. Every consumer reads `vehicle_listings` (86 columns, live) as its base row. Only three surfaces read the truth engine (`vehicle_facts` / `vehicle_snapshots`): the internal Vehicle File truth card, `autofilm-feed`, and `factory-sticker-orchestrate` itself. The Passport, stickers, Description Intelligence, inventory, reports, leads, audit packet and compliance digests never touch `vehicle_facts`.
2. Of the twelve critical fields, `vehicle_facts` carries nine (year, make, model, trim, mileage, advertised retail, MSRP, engine, drivetrain, condition minus VIN and stock); it has no `stock_number` or `vin` fact at all (20 distinct fact keys live). The ingest does push a `stock_number` candidate (`ingest.ts:142`, `listing.stock_number ?? mc.stock_no`) but both inputs are always null: the only stock writer is `vehicle_files.stock_number` (`marketcheck-sync/index.ts:984,1022,1029`; comment `:1036-1037`) and `mc_attributes` never receives `stock_no` (`:1132-1145`). Stock lives only on `vehicle_files.stock_number` (130/130 joined rows); `vehicle_listings` has no stock column and `mc_attributes.stock_no|stock|stock_number` is null on 131/131 unarchived rows.
3. The Passport's price arithmetic reads `vehicle_listings.price / advertised_price_before_doc / doc_fee / website_sale_price / dealer_discount / retail_cash / mc_attributes.msrp / market_value` and derives everything through `derivePassport -> buildPassportSaleCard -> buildSalePriceCard`. The price input is mode-dependent (`resolveDisplayPrice`, `priceModel.ts:195-213`): the pilot tenant runs `price_display_mode = website_sale_price` with `advertised_includes_doc_fee = true` (live `dealer_profiles.settings`, Q17), so the served Total Advertised Price is `vehicle_listings.price` (the MarketCheck syndication figure) and Vehicle Selling Price is `price - doc_fee` (`saleCard.ts:24-26`); `advertised_price_before_doc` is NOT the displayed input on Harte. On 5 of the 20 pilot VINs with a same-day dealer-page observation the served total differs from the dealer's own page (Q17; P7). Section 5 lists every column so a PASSPORT-SAFE projection can be proven equal.
4. Stale price reaching a consumer today: the Vehicle File truth card prints `vehicle_facts.advertised_price` labelled "Dealer stated" (blue; `factStatus` returns `dealer_entered` for `source_kind = dealer_confirmed` before the VERIFIED branch, `VehicleTruthCard.tsx:80-86`, `STATUS_LABEL:36`) while 99 of 118 unarchived VINs disagree with the `vehicle_listings.price` shown on the same page (32 below the live price, max gap $12,379). The fact is not an independent verification: it is a copy of `vl.price` taken at truth-run time (`ingest.ts:141`, `dealer_confirmed`/`VERIFIED`), and all 99 disagreeing facts have `observed_at` older than both `price_last_verified_at` and `updated_at` (live Q12) — STALE, not CONFLICTED. No age is rendered. AutoFilm now withholds it (Gate 0 §5.3).
5. Conflicted MSRP reaching customers: the Passport's MSRP anchor is `mc_attributes.msrp`, the MarketCheck `/v2/dealerships/inventory` feed field `l.msrp` (`marketcheck-sync/index.ts:1134`); `vehicle_facts.total_msrp` (VERIFIED) is read from `mc_attributes.total_msrp` first (`ingest.ts:193-194`), which `marketcheck-specs` lifts from the NeoVIN window-sticker build sheet (`marketcheck-specs/index.ts:310`; preserved across syncs by `DECODE_OWNED_KEYS`, `marketcheck-sync/index.ts:95-97`; live `specs_source = neovin` on all, `mc.total_msrp` equals the fact on 104 of 105).
